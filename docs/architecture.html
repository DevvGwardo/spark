Event Contract

One schema source for bridge → Node → UI events and errors · Pydantic is the source of truth

SSE EVENTS

  • → Every custom delta key is a Pydantic model with a constructor; main.py never builds a payload as a dict literal
  • → Keys: tool_activity · tool_call_begin/delta/end · agent_status · agent_notice(_clear) · computer_use_frame · server_tool_event · fallback_switch · transport_status · usage · approval_request · plan_update · stream_retry
  • → Node validates each key with HERMES_EVENT_SCHEMAS[key].safeParse in normalizeHermesAgentLoopPayload
  • → Unknown keys: logged once per type, then dropped
  • → Known key that fails validation: logged as an error but still forwarded, so the UI never silently loses tool state
  • → Adapter-owned payloads (agent_notice, computer_use_frame, server_tool_event) are open objects, because hermes-agent owns their fields
  • → Golden streams in hermes-bridge/fixtures/sse/ (agent-loop, ACP, runs, swarm) are replayed by both pytest and vitest

ERROR ENVELOPE

  • → Every Hermes error from Node to the UI: { error: { code, message, retryable, details? } }
  • → The bridge emits the same envelope from a FastAPI handler for BridgeError
  • → BridgeClient maps transport failures onto it; ChatErrorBanner switches on code, with no message regexes
  • → details carries actionable extras (suggested_models, retry_after_ms, approval_id …)
